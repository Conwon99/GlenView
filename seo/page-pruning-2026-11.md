# Page pruning for spam-update compliance (Nov 2026)

Source: Google Search Console Performance export, last 16 months (to 2026-11-01), web search.
Full per-URL list: `seo/page-pruning-2026-11.csv`.

## Update: all location pages removed

After the first pass (below), every location page was removed:

- 38 town pages (`/[town]/`) now 301 to `/`
- the 30 remaining town+service pages (`/[town]/[service]/`) now 301 to `/[service]/`
  (the 274 already removed now go to the service page too, so there are no redirect chains)
- `/locations/` now 301s to `/`

The town names still appear as plain text, without links, in the "Areas We Cover"
section, and the footer "Locations" link column is gone. The sitemap now lists 14 URLs.
The redirects are 3 rules in `vercel.json`, generated by
`scripts/generate-location-service-redirects.mjs`. Every rule matches with or without a
trailing slash.

Sections 1 and 2 below are now superseded. They are kept for the record.

## The risk

The site generates **358 URLs**, of which **304 are town × service pages**
(`/[location]/[service]/`: 38 towns × 8 services). Each one uses the same template
with the town name swapped in. Google's spam policies call this **scaled content
abuse / doorway pages**, and it is the pattern most likely to get the whole site
demoted, not just those pages.

## 3. Core pages: keep, but tidy up

## 4. Technical issue found

Google has indexed some **non-trailing-slash duplicates**, e.g.
`/larbert/patio-cleaning`, `/gutter-cleaning`, `/stepps/driveway-cleaning`. Add a
Vercel rule to 301 non-slash URLs to the slash version so duplicates stop being indexed.
